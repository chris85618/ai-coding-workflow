## 背景

- **觸發 Stage/Phase**: Stage 3（治理架構自舉）
- **觸發事件**: ADR 缺口盤點 — 雙 Agent 迭代協議為 Stage 3-8 的核心執行機制，但缺乏 ADR 等級的設計決策記錄。相關 ADR (ADR-GOV-009 級聯同步、ADR-GOV-019 ADG/PAG 增強) 僅涉及側面改善，未記錄核心設計理由。
- **前置條件**: iter-loop.md skill 已定義完整 Step 1-6 執行協議
- **約束**: 協議需支援所有 Stage 3-8 的差異化審查維度

## 決策

我們決定採用「雙 Agent 發散-收斂迭代 + 不動點收斂 + HITL 終審」的三層迭代架構：

1. **Agent α（破綻發掘者）**: 依各 Stage 審查維度進行窮盡式批判，產出按嚴重度排序的問題清單
2. **Agent β（收斂整合者）**: 對每個問題執行六步決策流（分類 → 奧卡姆剃刀 → 前提窮盡 → 併吞分析 → 循環依賴破解 → 邊界內化），產出自包含改善文件
3. **不動點收斂**: AI 自主迭代直至所有發現皆 YAGNI (REACHED) 或趨勢發散 (DIVERGING)，才提交 HITL
4. **HITL 終審**: 人類僅在 AI 收斂後介入，而非每輪迭代都介入；可選擇加入新需求重啟或通過

完整執行協議定義在 `skills/workflow-skills/iter-loop.md`。

## 理由

- **支持證據**: 傳統「每輪 HITL」模式導致人類疲勞和品質下降；不動點收斂機制讓 AI 自主達到穩定態後再交付審查
- **權衡取捨**: AI 自主收斂可能過度迭代（投入超必要的計算資源）→ 以 DIVERGING 偵測機制限制
- **風險接受**: AI 可能將應為 HIGH 的問題錯判為 YAGNI → 緩解措施：HITL 終審保留完整否決權

## 替代方案

| 方案 | 優點 | 缺點 | 拒絕理由 |
|------|------|------|---------|
| 每輪 HITL 審查 | 人類完全控制每輪 | 人類疲勞、審查品質隨輪次下降 | 不可擴展 (ADR-GOV-016 Ockham's Razor) |
| 固定輪次（例如恰好 3 輪） | 可預測 | 品質不穩定：簡單問題過度迭代、複雜問題不足 | 違反務實簡潔性 |
| 純單 Agent（無 α/β 分離） | 簡單 | 批判和整合混在同一思維流中，品質下降 | 違反 SRP、認知偏誤風險 |

## 後果

**正面**：
- AI 自主收斂減少人類介入次數（從 N 次降至 1 次）
- 發散偵測防止無限迭代
- Agent α/β 分離實現批判與建設的認知解耦

**負面**：
- 不動點判定的 YAGNI 閾值依賴 AI 判斷（存在主觀性）
- DIVERGING 狀態需要人類方向指引才能恢復
