# ADR-GOV-014: 事實優先失敗報告 (Factual Reporting Mandate)

> **狀態**: Accepted
> **日期**: 2026-05-14
> **類別**: GOVERNANCE
> **決策者**: AI-Proposed+HITL
> **追溯**: NFR-001
> **整合來源**: Omega v9.8 Foundry Generation

---

## 背景

- **觸發 Stage/Phase**: 治理層（Omega v9.8 整合）
- **觸發事件**: 分析 Omega v9.8 規格書，識別出 LLM 失敗報告中的擬人化藉口問題
- **前置條件**: Prompt Defense Baseline 無失敗報告格式約束
- **約束**: LLM 傾向產生擬人化敘事（「我感到困惑」「我忽略了」）

## 決策

我們決定在 Prompt Defense Baseline 中加入「事實優先」強制指令：當報告失敗或錯誤時，僅陳述可觀測事實、技術根因與修正措施，絕對禁止擬人化藉口或敘事性辯解。

## 理由

- **支持證據**: Omega 分析揭示 LLM 擬人化報告損害使用者知情權和主權
- **權衡取捨**: 報告可能顯得「冷硬」，但資訊精確度提升

## 替代方案

| 方案 | 優點 | 缺點 | 拒絕理由 |
|------|------|------|----------|
| 允許擬人化 + 事實 | 報告更「友好」 | 擬人化敘事可能掩蓋技術根因 | 資訊精確度優先 |
| 不設約束 | 靈活 | 無品質保障 | 不可接受 |

## 後果

**正面**：失敗報告資訊密度提升，使用者能直接定位問題
**負面**：報告風格可能較為生硬

## 影響分析

- **爆炸半徑**: 1（AGENTS.md Prompt Defense Baseline）
- **嚴重度**: MODERATE


## 流程變更

- **修改前規則**: 無失敗報告格式約束
- **修改後規則**: Prompt Defense Baseline 含「事實優先」指令
- **影響範圍**: 所有 session 的錯誤報告
