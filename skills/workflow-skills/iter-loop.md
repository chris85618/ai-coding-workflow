# Skill: 雙 Agent 迭代迴圈

> **觸發條件**：Stage 3-8 的每一輪迭代
> **輸入**：該 Stage 的審查維度表、前輪產出物
> **輸出**：改善後的產出物（已通過微驗證）

---

## 執行協議

```
Step A: Agent α（破綻發掘者）
─────────────────────────────
1. 載入該 Stage 的審查維度表
2. 逐維度對當前產出物進行窮盡式批判
3. 對每個發現標注：
   - 嚴重度：CRITICAL / HIGH / MEDIUM / LOW / YAGNI
   - 影響範圍：哪些 ID 受影響
   - 建議方向（不是解法，是方向）
4. 產出：問題清單（按嚴重度降序排列）

Step B: Agent β（收斂整合者）
─────────────────────────────
對 Agent α 的每個問題，依序執行決策流：

1. 分類：是 bug / 設計缺陷 / 遺漏 / 風格 / YAGNI？
2. 奧卡姆剃刀：最簡方案是什麼？
3. 前提窮盡：修復前提是否完整？是否有隱含假設？
4. 併吞分析：此修復能否順便解決其他問題？
5. 循環依賴破解：修復是否引入新的循環？
6. 邊界內化：修復後的系統邊界是否更清晰？

產出：完整自包含改善文件（不引用外部內容）

Step M: 微驗證迴圈（每個改善後立即執行）
────────────────────────────────────────
→ 觸發 skills/workflow-skills/micro-validation.md
→ 觸發 skills/workflow-skills/impact-analysis-exec.md
→ 全數通過才進入 Step C
→ 任一失敗 → 自主修復 → 重新執行 Step M
→ 修復 3 次仍失敗 → 上報至 HITL

Step C: 👤 HITL 迭代閘門
────────────────────────
呈現本輪摘要：
- Agent α 發現的問題數量和嚴重度分佈
- Agent β 的修復摘要
- 微驗證結果

使用者選擇：
[1] 繼續迭代 → 回到 Step A
[2] 加入新需求後繼續 → 更新輸入 → 回到 Step A
[3] 通過 ✅ → 進入出口閘門驗證
```

## 不動點偵測

```
IF Agent α 本輪所有發現的嚴重度皆為 YAGNI:
  → 自動建議：「Agent α 已達不動點，建議終止迭代」
  → 使用者可選擇 [3] 通過 或 [1] 強制再迭代一輪
```

## 出口閘門驗證（通用模板）

通過 HITL 後，執行出口閘門驗證：

```
出口閘門 = 該 Stage 的原有檢查項
         + 追溯矩陣驗證（見 TRACEABILITY.md）
         + 影響分析完成確認
         + 所有文件已寫入 docs/

全數通過 → 進入下一 Stage
任一失敗 → 回到 Step A 繼續迭代
```
