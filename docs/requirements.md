## Functional Requirements

### FR-001: 頂層指揮器文件結構

**描述**：AGENTS.md 必須作為唯一進入點，以呼叫鏈方式引用所有 phase/stage 文件和 skill 文件。
**追溯**：FEA-001 (decomposes)

### FR-002: Phase/Stage 文件分離

**描述**：每個 Phase (0-2, 9-10) 和 Stage (3-8) 擁有獨立的 .md 文件，存放在 `docs/phases/` 和 `docs/stages/`。
**追溯**：FEA-001, FEA-009 (decomposes)

### FR-003: Skill 文件獨立

**描述**：所有可執行協議（迭代迴圈、S2C 分析、安全審計等）從 docs 獨立為 `skills/workflow-skills/*.md`。
**追溯**：FEA-001, FEA-008 (decomposes)

### FR-004: ID 前綴指派

**描述**：支援 16 種 ID 前綴（BG/S/FEA/FR/NFR/UC/ADR/ALG/CLS/EVT/INV/SC/TC/DEBT/RISK/IMP），每種前綴在指定 Stage 指派。
**追溯**：FEA-002 (decomposes)

### FR-005: 雙向追溯鏈驗證

**描述**：正向追溯（BG→FEA→FR→UC→SC→TC）和反向追溯（TC→SC→UC→FR→FEA→BG）皆可自動驗證。
**追溯**：FEA-002 (decomposes)

### FR-006: 語意一致性檢查

**描述**：追溯鏈上的每對上下游 ID 必須通過語意一致性判定（方向一致、範圍收斂、意圖保留、無矛盾、完備覆蓋）。
**追溯**：FEA-002 (decomposes)

### FR-007: 左移微驗證觸發

**描述**：每個微動作（新增/修改/刪除 ID）後自動觸發微驗證迴圈（Step 0 格式驗證至 Step 7 變更紀錄+根因左移，含 Step 5.5 全方向追溯 + Step 5.7 LESSON 重用）。
**追溯**：FEA-002 (decomposes)

### FR-008: 影響分析自動執行

**描述**：每次修改自動計算爆炸半徑、分類嚴重度（COSMETIC/MINOR/MODERATE/MAJOR），MAJOR 自動上報 HITL。
**追溯**：FEA-003 (decomposes)

### FR-009: 影響分析紀錄持久化

**描述**：每次影響分析產出變更紀錄，寫入對應 ADR 的「變更紀錄」區段。
**追溯**：FEA-003 (decomposes)

### FR-010: 技術債登記冊獨立

**描述**：每個專案維護獨立的 `docs/tech-debt-register.md`，含 DEBT-xxx 項目和 RICE 分數。
**追溯**：FEA-004 (decomposes)

### FR-011: 技術債 RICE 排序

**描述**：每個 DEBT-xxx 計算 RICE 分數並分類至四象限（Quick Wins/Strategic/Incremental/Avoid）。
**追溯**：FEA-004 (decomposes)

### FR-012: Agent α/β 迭代迴圈

**描述**：Stage 3-8 各自定義審查維度，共用 `iter-loop.md` 迭代協議（Step A → B → M → C）。
**追溯**：FEA-005 (decomposes)

### FR-013: 不動點判定

**描述**：Stage 3-8 迭代中，每輪 Step M 通過後執行不動點判定（Step F）：若 Agent α 所有發現皆為 YAGNI → REACHED → 觸發 HITL；若有 CRITICAL+HIGH 未收斂 → DIVERGING → 觸發 HITL；其他情況 → NOT_REACHED → 自主繼續迭代。
**追溯**：FEA-005 (decomposes)

### FR-014: HITL 收斂確認（AI-first 模型）

**描述**：HITL 閘門僅在 AI 自主達到不動點（REACHED 或 DIVERGING）後觸發，提供兩個選項：[1] 加入新需求後繼續（回到 Step A）、[2] 通過 ✅（進入出口閘門）。AI 自主迭代期間不觸發 HITL。
**追溯**：FEA-005 (decomposes)

### FR-015: SonarCloud 門檻定義

**描述**：Stage 8 品質閘門門檻：覆蓋率 ≥80%（新程式碼 ≥85%）、零 Critical 漏洞、技術債比率 ≤5%、Major Smells ≤10。
**追溯**：FEA-006 (decomposes)

### FR-016: 三層安全審計串接

**描述**：Layer 1(/cso) + Layer 2(AgentShield) + Layer 3(SkillFortify) 依序執行，任一層 HIGH+ → 回修設計。
**追溯**：FEA-007 (decomposes)

### FR-017: S2C Skill 標準格式

**描述**：每個 S2C skill 文件包含：觸發條件、輸入、輸出、執行協議步驟。
**追溯**：FEA-008 (decomposes)

### FR-018: docs/ 結構化層次

**描述**：docs/ 包含 governance/（5 文件）、phases/（5 文件）、stages/（6 文件）和專案文件驅動產出物。
**追溯**：FEA-009 (decomposes)

### FR-019: 工作流狀態機持久化

**描述**：`docs/workflow-state.md` 作為目標導向 WBS 的單一事實來源，記錄當前 Phase/Stage、迭代輪次、閘門狀態、待處理上報。每完成一個 WBS leaf 後立即更新，完成項在其他文件記錄後移除。
**追溯**：FEA-010 (decomposes)

### FR-020: 結構化迭代紀錄

**描述**：`docs/iteration-log.md` 以可機器解析的格式記錄每輪 Agent α findings（嚴重度/維度/受影響 ID）、Agent β resolutions、微驗證結果、不動點評估。每輪 Step A/B/M 完成後立即寫入。
**追溯**：FEA-010 (decomposes)

### FR-021: 中斷恢復協議

**描述**：偵測到 `docs/workflow-state.md` 存在且有進行中工作時，自動呈現恢復摘要（當前位置/已通過閘門/待處理工作/待處理上報），使用者確認後從斷點繼續。已通過的 HITL 閘門不可重做，未通過的不可跳過。
**追溯**：FEA-010 (decomposes)

### FR-022: 全鏈影響追溯

**描述**：影響分析除縱向主鏈（BG→FEA→FR→UC→...→TC）外，必須追溯所有方向的連結：ADR 的 justifies、NFR 的 constrains、RISK 的 mitigates、EVT 的 emitted-by、INV 的 formalizes 等。每個受影響 ID 的對應完整文件必須被讀取並驗證語意一致性。
**追溯**：FEA-002, FEA-003 (decomposes)

### FR-023: LESSON 重用機制

**描述**：執行 RCA 前，必須先掃描已存在的 LESSON-xxx，檢查是否有相同根因類別的過往記錄。若存在：表示左移守衛不足，對守衛本身執行 RCA 並強化，而非建立重複 LESSON。
**追溯**：FEA-002, FEA-010 (decomposes)

### FR-024: 跨切面一致性驗證

**描述**：當變更橫跨 2+ Stage/Phase 或變更 3+ 文件時，強制執行全矩陣重驗證、跨文件交叉檢查、覆蓋統計重算和過期引用掃描。確保所有變更作為一個整體形成一致的系統。

## UC-016: 文件自動化同步

**描述**：當開發者修改 `pyproject.toml` 中的專案元資料時，MkDocs 文件站點應在下次建置時自動套用這些變更。

**主要流程**：修改 `pyproject.toml` → 執行 `mkdocs build` → 驗證站點資訊
