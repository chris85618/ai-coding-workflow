# Requirements Register — Antigravity Integrated Workflow System

## Functional Requirements

### FR-001: 頂層指揮器文件結構

**描述**：WORKFLOW.md 必須作為唯一進入點，以呼叫鏈方式引用所有 phase/stage 文件和 skill 文件。
**追溯**：FEA-001 (decomposes)

### FR-002: Phase/Stage 文件分離

**描述**：每個 Phase (0-2, 9-10) 和 Stage (3-8) 擁有獨立的 .md 文件，存放在 `docs/phases/` 和 `docs/stages/`。
**追溯**：FEA-001, FEA-009 (decomposes)

### FR-003: Skill 文件獨立

**描述**：所有可執行協議（迭代迴圈、S2C 分析、安全審計等）從 docs 獨立為 `skills/workflow-skills/*.md`。
**追溯**：FEA-001, FEA-008 (decomposes)

### FR-004: ID 前綴指派

**描述**：支援 16 種 ID 前綴（BG/S/FEA/FR/NFR/UC/ADR/ALG/CLS/EVT/INV/SC/TC/DEBT/RISK/IMP），每種前綴在指定 Stage 指派。
**追溯**：FEA-002 (decomposes)

### FR-005: 雙向追溯鏈驗證

**描述**：正向追溯（BG→FEA→FR→UC→SC→TC）和反向追溯（TC→SC→UC→FR→FEA→BG）皆可自動驗證。
**追溯**：FEA-002 (decomposes)

### FR-006: 語意一致性檢查

**描述**：追溯鏈上的每對上下游 ID 必須通過語意一致性判定（方向一致、範圍收斂、意圖保留、無矛盾、完備覆蓋）。
**追溯**：FEA-002 (decomposes)

### FR-007: 左移微驗證觸發

**描述**：每個微動作（新增/修改/刪除 ID）後自動觸發 8 步微驗證迴圈（Step 0 格式驗證至 Step 7 變更紀錄+根因左移）。
**追溯**：FEA-002 (decomposes)

### FR-008: 影響分析自動執行

**描述**：每次修改自動計算爆炸半徑、分類嚴重度（COSMETIC/MINOR/MODERATE/MAJOR），MAJOR 自動上報 HITL。
**追溯**：FEA-003 (decomposes)

### FR-009: 影響分析紀錄持久化

**描述**：每次影響分析產出 IMP-xxx 紀錄，寫入 `docs/change-log.md`。
**追溯**：FEA-003 (decomposes)

### FR-010: 技術債登記冊獨立

**描述**：每個專案維護獨立的 `docs/tech-debt-register.md`，含 DEBT-xxx 項目和 RICE 分數。
**追溯**：FEA-004 (decomposes)

### FR-011: 技術債 RICE 排序

**描述**：每個 DEBT-xxx 計算 RICE 分數並分類至四象限（Quick Wins/Strategic/Incremental/Avoid）。
**追溯**：FEA-004 (decomposes)

### FR-012: Agent α/β 迭代迴圈

**描述**：Stage 3-8 各自定義審查維度，共用 `iter-loop.md` 迭代協議（Step A → B → M → C）。
**追溯**：FEA-005 (decomposes)

### FR-013: 不動點偵測

**描述**：當 Agent α 僅剩 YAGNI 級質疑時，自動建議終止迭代。
**追溯**：FEA-005 (decomposes)

### FR-014: HITL 閘門三選項

**描述**：每個 HITL 閘門提供三個選項：[1] 繼續迭代、[2] 加入新需求、[3] 通過。
**追溯**：FEA-005 (decomposes)

### FR-015: SonarCloud 門檻定義

**描述**：Stage 8 品質閘門門檻：覆蓋率 ≥80%（新程式碼 ≥85%）、零 Critical 漏洞、技術債比率 ≤5%、Major Smells ≤10。
**追溯**：FEA-006 (decomposes)

### FR-016: 三層安全審計串接

**描述**：Layer 1(/cso) + Layer 2(AgentShield) + Layer 3(SkillFortify) 依序執行，任一層 HIGH+ → 回修設計。
**追溯**：FEA-007 (decomposes)

### FR-017: S2C Skill 標準格式

**描述**：每個 S2C skill 文件包含：觸發條件、輸入、輸出、執行協議步驟。
**追溯**：FEA-008 (decomposes)

### FR-018: docs/ 結構化層次

**描述**：docs/ 包含 governance/（3 文件）、phases/（5 文件）、stages/（6 文件）和專案文件驅動產出物。
**追溯**：FEA-009 (decomposes)

## Non-Functional Requirements

### NFR-001: 純 Markdown 可讀性

**描述**：所有文件必須為純 Markdown 格式，不使用可執行程式碼，任何文字編輯器皆可閱讀。
**追溯**：FEA-009 (constrains)

### NFR-002: 子模組唯讀

**描述**：不修改 ECC/gstack/UA/SkillFortify 子模組，僅引用其工具。
**追溯**：FEA-001 (constrains)

### NFR-003: 向下相容

**描述**：GEMINI.md/AGENTS.md/CLAUDE.md 格式變更不得破壞既有 symlink 和工具讀取。
**追溯**：FEA-001 (constrains)

### NFR-004: 追溯矩陣驗證效率

**描述**：微驗證迴圈在 3 次自主修復內解決問題，超過則上報 HITL。
**追溯**：FEA-002 (constrains)
