## SC-003: 迭代 Stage 收斂

**追溯**: UC-003 (covers), INV-003, INV-004, INV-005 (verifies)

```gherkin
Scenario: Agent α/β 迭代自主收斂（Step F REACHED）
  Given Stage N 已就緒
  When Agent α 批判後所有發現為 YAGNI 級
  Then Step F 判定 fixed_point = REACHED
  And HITL 收斂確認觸發
  And HITL 確認後 Stage 狀態變為 PASSED [INV-003]

Scenario: 迭代達上限強制 HITL（DIVERGING）
  Given Stage N 正在迭代
  And 迭代次數已達 10 [INV-004]
  When 第 11 次迭代嘗試
  Then Step F 判定 fixed_point = DIVERGING
  And 系統強制上報 HITL
  And 不再自動迭代

Scenario: NOT_REACHED 自主繼續（不觸發 HITL）
  Given Step M 微驗證通過 [INV-005]
  And 仍有 CRITICAL 或 HIGH 未收斂發現
  When Step F 執行判定
  Then fixed_point = NOT_REACHED
  And Agent α 自動重新批判
  And iterationCount += 1
  And HITL 不觸發

Scenario: HITL 選擇加入新需求
  Given HITL 收斂確認閘門顯示（fixed_point 已達）
  When HITL 選擇 [1] 加入新需求後繼續
  Then 輸入更新
  And Agent α 以新輸入重新批判
```

## SC-004: 微驗證六步序列

**追溯**: UC-004 (covers), INV-006, INV-007, INV-008, INV-009, INV-010, INV-011 (verifies)

```gherkin
Scenario: 微驗證六步全部通過
  Given 一個新 ID 被指派
  When 觸發微驗證
  Then 六步依序執行 [INV-010]
  And 結構檢查通過（ID 格式正確）
  And 正向追溯通過（有下游或為末端）[INV-007]
  And 反向追溯通過（有上游或為源頭）[INV-007]
  And 語意一致通過 [INV-009]
  And 孤兒偵測通過
  And 影響分析觸發

Scenario: 微驗證第 3 步失敗自主修復
  Given 反向追溯檢查失敗
  When 自主修復嘗試 1 次
  Then 自動補上遺漏的上游連結
  And 重新驗證通過

Scenario: 微驗證修復 3 次仍失敗上報
  Given 某步驟檢查失敗
  And 自主修復已嘗試 3 次 [INV-011]
  When 第 4 次修復嘗試
  Then 系統上報 HITL
  And 該步驟標記為 ESCALATED

Scenario: 自連結被拒絕
  Given 嘗試建立 TraceLink
  When source 和 target 為同一 ID [INV-008]
  Then 連結被拒絕
  And 錯誤訊息指出自連結禁止

Scenario: ID 唯一性違反
  Given 已存在 FR-001
  When 嘗試建立第二個 FR-001 [INV-006]
  Then 建立被拒絕
  And 錯誤訊息指出 ID 重複
```

## SC-005: 影響分析爆炸半徑

**追溯**: UC-005 (covers), INV-012, INV-013 (verifies)

```gherkin
Scenario: COSMETIC 級修改
  Given 修改一個 ID 且無下游
  When 影響分析計算
  Then blast_radius = 0
  And severity = COSMETIC
  And IMP-xxx 寫入 change-log.md

Scenario: MINOR 級修改
  Given 修改一個 ID 且下游 ≤ 3 且同 Stage
  When 影響分析計算
  Then severity = MINOR [INV-012]

Scenario: MAJOR 級修改觸發 HITL
  Given 修改一個 ID 且下游 > 10 或跨 2+ Stage
  When 影響分析計算
  Then severity = MAJOR
  And 系統自動上報 HITL [INV-013]
  And IMP-xxx 寫入 change-log.md

Scenario: 嚴重度單調性
  Given 兩個修改 A (blast=5) 和 B (blast=15)
  When 分別計算嚴重度
  Then severity(B) ≥ severity(A) [INV-012]
```

## SC-007: SonarCloud 品質閘門

```gherkin
Scenario: SonarCloud 全門檻通過
  Given 所有測試通過
  When 執行 SonarCloud 掃描
  Then 覆蓋率 ≥ 80%
  And 零 Critical 漏洞
  And 技術債比率 ≤ 5%
  And 品質閘門 = PASS

Scenario: 覆蓋率不足自主修復
  Given SonarCloud 掃描覆蓋率 = 72%
  When 自主修復嘗試
  Then 補充測試案例
  And 重新掃描

Scenario: 自主修復 3 次仍失敗
  Given SonarCloud 門檻未達標
  And 自主修復已嘗試 3 次
  When 第 4 次嘗試
  Then 上報 HITL
```
