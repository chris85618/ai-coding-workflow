# Impact Analysis Gateway

> **強制等級**：任何修改、無例外。
> 每一個對帶 ID 產出物的修改（無論大小）皆必須自主執行本協議。

---

## 觸發條件

本協議在以下任一情況發生時**強制自主執行**：

1. 新增任何帶 ID 的產出物
2. 修改任何帶 ID 的產出物（內容、描述、連結）
3. 刪除任何帶 ID 的產出物
4. 修改任何追溯連結
5. 修改任何已通過 HITL 閘門的產出物
6. 修改任何 Stage 的審查維度或工具配置

---

## 執行協議

```
┌─────────────────────────────────────────────────────────┐
│  IMPACT ANALYSIS GATEWAY（每次修改自動執行）             │
│                                                         │
│  Step 1: 識別變更                                       │
│  → 記錄變更的 ID 和變更內容                             │
│  → 分類：新增 / 修改 / 刪除                             │
│  → 記錄變更時間戳和觸發 Stage                           │
│                                                         │
│  Step 2: 正向影響追溯                                   │
│  → 從變更 ID 沿正向追溯鏈走訪所有下游 ID                │
│  → 標記每個下游 ID 為「可能受影響」                     │
│  → 遞迴展開至追溯鏈末端                                │
│                                                         │
│  Step 3: 反向影響追溯                                   │
│  → 從變更 ID 沿反向追溯鏈走訪所有上游 ID                │
│  → 檢查上游 ID 的語意是否仍與變更後內容一致             │
│  → 標記不一致的上游 ID                                  │
│                                                         │
│  Step 4: 爆炸半徑計算                                   │
│  → blast_radius = count(affected_downstream)            │
│                   + count(inconsistent_upstream)          │
│  → 跨 Stage 影響 = 受影響 ID 橫跨幾個 Stage            │
│                                                         │
│  Step 5: 嚴重度分類                                     │
│  ┌──────────────────────────────────────────┐            │
│  │ COSMETIC (blast_radius = 0)             │            │
│  │ → 僅格式/拼寫修正，無語意變更           │            │
│  │ → 動作：記錄 IMP-xxx，繼續              │            │
│  ├──────────────────────────────────────────┤            │
│  │ MINOR (blast_radius = 1-3, 同 Stage)    │            │
│  │ → 動作：自主更新受影響 ID               │            │
│  │ → 重新執行微驗證迴圈                    │            │
│  │ → 記錄 IMP-xxx                          │            │
│  ├──────────────────────────────────────────┤            │
│  │ MODERATE (blast_radius = 4-10           │            │
│  │          或跨 1 個 Stage)               │            │
│  │ → 動作：自主更新受影響 ID               │            │
│  │ → 重新驗證受影響 Stage 的出口閘門       │            │
│  │ → 記錄 IMP-xxx                          │            │
│  ├──────────────────────────────────────────┤            │
│  │ MAJOR (blast_radius > 10                │            │
│  │       或跨 2+ Stage)                    │            │
│  │ → 動作：暫停工作流                      │            │
│  │ → 產出完整影響報告                      │            │
│  │ → 上報至 HITL 閘門等待核准              │            │
│  │ → 核准後自主更新所有受影響 ID           │            │
│  │ → 重新驗證所有受影響 Stage 出口閘門     │            │
│  │ → 記錄 IMP-xxx                          │            │
│  └──────────────────────────────────────────┘            │
│                                                         │
│  Step 6: 產出影響分析紀錄                               │
│  → 寫入 docs/impact-log.md                              │
│  → 指派 IMP-xxx ID                                      │
│  → 更新追溯矩陣                                        │
└─────────────────────────────────────────────────────────┘
```

## 影響分析紀錄格式

每個 IMP-xxx 紀錄包含：

```markdown
### IMP-001: [變更摘要]

**觸發時間**: [ISO 8601]
**觸發 Stage**: Stage [N]
**變更類型**: 新增 / 修改 / 刪除
**變更 ID**: [變更的 ID]
**變更內容**: [變更前] → [變更後]

**影響分析**:
- 爆炸半徑: [N] 個 ID
- 跨 Stage 影響: [N] 個 Stage
- 嚴重度: COSMETIC / MINOR / MODERATE / MAJOR

**受影響 ID**:
| ID | Stage | 影響類型 | 處理狀態 |
|----|-------|---------|---------|
| FR-003 | Stage 3 | 語意需更新 | ✅ 已修復 |
| UC-005 | Stage 3 | 連結需更新 | ✅ 已修復 |
| SC-012 | Stage 7 | 場景需修改 | ✅ 已修復 |

**閘門重新驗證**:
- [ ] Stage 3 出口閘門：✅ 重新通過
- [ ] Stage 7 出口閘門：✅ 重新通過

**處理狀態**: ✅ 完成
```

## 工具整合

| 情境 | 工具 | 用法 |
|------|------|------|
| 程式碼變更影響 | `/understand-diff` | 分析 diff 的元件影響和爆炸半徑 |
| 文件變更影響 | 手動追溯 | 沿追溯鏈標記受影響 ID |
| 跨 Stage 影響 | `/review` | 程式碼審查跨 Stage 一致性 |
| 自主修復驗證 | 微驗證迴圈 | 執行 TRACEABILITY.md 的微動作驗證 |

---

## 禁止行為

1. **禁止跳過影響分析**：無論修改多小，皆必須執行
2. **禁止僅更新變更 ID 而不更新下游**：必須遞迴傳播
3. **禁止在 MAJOR 影響下自主決定**：必須上報 HITL
4. **禁止在未完成影響分析前進入下一個微動作**
