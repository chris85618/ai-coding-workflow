## 2. Features to Absorb (Prioritized)

### P0: Repo Map with Tree-Sitter (from Aider)

**What**: Build a condensed repository map using tree-sitter AST parsing.
Extract class/function/method signatures, rank by PageRank on import graph.
Send map (not full files) to LLM for context awareness.

**Why**: Dramatically reduces token usage. Aider's core innovation.
Our Phase 1 (code comprehension) currently has no structured approach.

**Design integration**:
- New ALG: `ALG-006 RepoMapBuilder` (deterministic: tree-sitter parse + PageRank)
- New CLS: `CLS-015 RepoMap` (domain model for repository structure map)
- Integrates into Phase 1 node and Agent α/β context injection
- Uses `py-tree-sitter-languages` for parsing, `networkx` for PageRank
- Token budget parameter controls map size

### P1: Atomic Git Commits per Stage (from Aider)

**What**: Auto-commit all changes at each stage completion.
Each commit = one atomic unit of work with descriptive message.

**Why**: Full traceability of AI-generated changes. Easy rollback.
Integrates with our GitKraken MCP adapter.

**Design integration**:
- Extend `MCPGateway` port with `auto_commit(stage, message)` method
- Call at end of each stage node (after write_docs)
- Commit message format: `[Stage N] {stage_name}: {summary}`
- Uses existing GitKraken MCP `git_commit` tool

### P1: Lifecycle Hooks (from Claude Code)

**What**: Deterministic hook points at key lifecycle events.
Hooks run shell commands for enforcement, not LLM-dependent.

**Why**: Enforces quality gates deterministically (ruff format, lint).
Replaces our governance protocol's "AI must remember" with "system enforces."

**Design integration**:
- New domain service: `CLS-016 HookRunner` (runs registered hooks)
- Hook events: `PreStageStart`, `PostStageComplete`, `PreDocWrite`, `PostDocWrite`
- Hooks are registered via config, not hardcoded
- Default hooks: `ruff format`, `ruff check`, crosshair verify
- Hook results feed back into DAG state as warnings/errors

### P0: Provider-Agnostic LLM Gateway with Strategy Pattern (from OpenCode/Aider)

**What**: Support multiple LLM providers without code changes.
Route requests based on task complexity using Strategy Pattern.

**Why**: Not locked to one vendor. Cost optimization is critical.
Agent α uses reasoning model (expensive), Agent β uses editing model (cheap).
User explicitly requires free model selection per task difficulty.

**Design integration**:
- New CLS: `CLS-017 LLMStrategySelector` (Strategy Pattern domain service)
- New CLS: `CLS-018 ModelConfig` (Value Object for model parameters)
- New ALG: `ALG-008 ModelSelector` (deterministic: task_type → model config)
- `LLMGateway` port receives `ModelConfig` parameter
- Agent α uses high-reasoning model (o1/Opus)
- Agent β uses fast-editing model (Sonnet/GPT-4o)
- Graceful degradation when provider is disabled
- Configurable per-project via `config.py`

### P2: Context Budget Control (from Aider)

**What**: Limit tokens sent to LLM per request.
Automatically select most relevant context within budget.

**Why**: Cost control + better LLM performance with focused context.

**Design integration**:
- New ALG: `ALG-007 ContextBudgetAllocator` (deterministic: priority ranking + truncation)
- Input: repo map, current files, budget limit
- Output: pruned context that fits within token budget
- Integrates with Agent α/β context injection

### P3: Auto-Format on Doc Write (from Claude Code PostToolUse)

**What**: Run ruff format automatically after every code generation.

**Why**: Guarantees consistent formatting without LLM remembering style rules.

**Design integration**:
- Handled by `CLS-016 HookRunner` with `PostDocWrite` event
- Default hook: `ruff format {file}` for .py files
- No manual invocation needed
